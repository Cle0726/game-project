# 剧情视觉资产一致性标准

本项目的剧情画面由三类可独立维护的资产组成：

1. **环境背景**：不包含可识别主角，负责地点、时间、天气与气氛。
2. **角色立绘**：透明背景，可跨场景复用，负责说话者身份与表情。
3. **关键 CG**：只用于不可替代的剧情瞬间，必须绑定人物身份参考与具体形态。

背景不能代替地图，概念设定图不能直接代替游戏立绘，旧的低清或抠坏状态图不能作为新图参考。

## 一、组合顺序

所有人物提示词固定按以下顺序组合：

1. `identity lock`：脸型、五官比例、发型、标志性配饰、体型。
2. `form lock`：日常态、律者态、战斗态或章节限定服装。
3. `eye profile`：虹膜、瞳孔、眼线、眼影、眼下纹路、泪痣。
4. `expression / pose`：只允许改变表情、手势和轻微姿势。
5. `chapter style`：章节色板、材质、光源和环境语言。
6. `camera`：画幅、景别、留白和角色位置。
7. `negative lock`：明确禁止的发色、服装、眼睛和配饰变化。

角色身份层永远高于章节风格层。更换画风版本时，只替换 `chapter style` 或 `render family`，不得改写人物身份锚点。

## 二、背景标准

- 统一使用 16:9 横向构图，推荐 1536×1024 或更宽的等比尺寸。
- 背景不出现可识别的核心人物，不出现文字、标志、水印和 UI。
- 预留左、中、右三处至少两处可放立绘的干净空间。
- 下方约 25% 避免高频细节，保证对白框可读。
- 室内外必须保留章节建筑语言和材料连续性，不能每张图换一种时代与地域。
- 夜景不能压成死黑；角色面部区域必须有可用的轮廓光或环境反射光。
- 同一章节中同一背景最多承担约三分之一剧情节点；地点、时间或叙事功能变化时应切换背景。

## 三、人物标准

- 核心角色继续使用 `default / smile / worried / serious / shocked / special` 六状态 API。
- 章节 NPC 只有反复发言或路线重要时才制作立绘；普通群像保留为背景元素。
- NPC 默认立绘一经通过，即成为后续状态图的唯一身份参考。
- 透明立绘必须从干净母图或首次通过的高质量默认立绘生成，不得从绿边、低清、已抠坏图片继续修补。
- 新增复用立绘优先生成在均匀中性灰底上，再用 BiRefNet 抠成透明 PNG；避免绿色或蓝色底色污染头发、丝带和半透明饰件边缘。
- 接入前放大检查脸、发型、衣领、袖口、手指、武器、鞋、发丝边缘和透明角落。

## 四、律者眼部层级

律者变身不允许只写“发光眼睛”。至少定义以下六层：

1. **原始虹膜层**：保留角色原有眼型与基础眼色关系。
2. **权能瞳孔层**：音符、雪花、几何刻线或章节专属符号。
3. **虹膜能量层**：由内向外的颜色渐变与环形光纹。
4. **眼线层**：上眼线方向、粗细、眼尾长度和是否分叉。
5. **眼影层**：颜色、边界、扩散形状及与服装图案的呼应。
6. **眼下标记层**：五线谱、金粉、泪光、泪痣或角色专属纹样。

不同类型不得混用：

- 自然觉醒律者：音符瞳、花瓣式眼影、金色谱线与泪光。
- 静默序列：银灰空洞虹膜、将熄暗金光，不使用华丽花瓣眼影。
- 登记/秩序型：克制几何刻线、清晰银灰瞳、精密但不空洞。
- 培育型：人工蚀刻般的瞳孔与极窄、精确的铂紫色眼影。
- 救赎恢复型：暗金光从瞳孔内部回填，眼影由冷硬边界转为有温度的反射。

官方《崩坏3》角色设计访谈强调眼睛色彩、渐变瞳孔与角色权能主题需要共同服务于人物气质；本项目只借鉴“主题—眼部—特效一致”的设计方法，不复制具体角色造型：

- https://www.hoyolab.com/article/20568750
- https://www.hoyolab.com/article/17039912

## 五、安娜形态硬锁

### 日常态

- 橙红色高马尾与长刘海。
- 清晰蓝眼，眼妆克制。
- 右眼下小泪痣必须可见。
- 圆环耳饰、黑色颈圈。
- 日常服装以深色外套、酒红或浅蓝衬衣为主，不出现黑金星网礼服。

### 律者态

- 深赤红至冷紫渐变的披散长发，不得保留日常高马尾。
- 冰蓝至蓝紫发光虹膜，瞳孔内是雪花与细乐谱环的组合。
- 上眼线为锐利黑色长翼，眼尾叠加酒红与深紫花瓣状眼影。
- 下睫毛处保留细金粉和极细谱线泪光，但不得遮住右眼下泪痣。
- 星雪花发饰、黑金星网礼服、冷紫半透明披纱固定不变。
- 禁止橙色高马尾、普通职业装、缺失泪痣、纯红瞳、无结构的烟熏眼妆。

## 六、运行与验收

- 场景视觉覆盖：`npm run visual:audit`
- 重复发言人物立绘覆盖：`npm run visual:speaker-guard`
- 核心人物六状态：`npm run character:guard`
- JavaScript 语法：`node --check game.js`
- 完整构建：`npm run portrait:build`

视觉审计只负责发现缺失和过度复用，不能替代人工验图。任何新人物图在接入前都必须与身份参考并排查看。
