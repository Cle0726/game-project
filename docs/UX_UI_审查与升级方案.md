# 《宿命回响：残响之途》UI 全面审查与升级方案

> 审查人：UX/交互设计师视角
> 审查范围：index.html / style.css (5555 行) / entrance.css / game.js 渲染逻辑
> 参考审美：原神 / 明日方舟 / FGO / 崩坏系列等大厂二次元叙事游戏的着陆页与 HUD 设计语言
> 审查时间：2026-07-02

---

## 一、总体判断

当前 UI **不是不好看，而是"信息密度过高 + 术语墙 + 双套布局并存"**。

`Team Dossier Override`（行 4051+）已经做出了真正向大厂看齐的精致设计——立绘卡 + 白底深色对撞 + color-mix 动态配色 + clamp 响应式。这说明项目**有能力做好**，但其余 80% 的界面还停留在"工程师感"的列表 + 文字按钮阶段，且因为**三层样式覆盖 + 87 个 CSS 变量 + 60 个自动生成的透明色 token + Final Cleanup 层的 !important 强制覆盖**，所有后续 UX 改进都会举步维艰。

**核心矛盾：美术资产已经很精致（约 100 张白金歌剧风资产），但 UI 容器没有跟上资产的精度。**

## 二、14 个具体问题（按严重程度分级）

### 🔴 P0 级（直接卡新玩家，必须最先修）

#### P0-1　首屏术语墙撞脸

**位置**：`#main-menu` 主菜单 → `entry-actions` 按钮组

**问题**：玩家打开游戏第一眼就看到：
- 「开始第一乐章」—— "乐章"是什么？
- 「调律抽取」—— "调律"是啥？"抽取"又是啥？
- 「存档记录」—— 这个还行
- 「系统设置」—— 这个还行

4 个按钮里 2 个含未解释术语。玩家会犹豫点哪个。

**大厂对照**：原神着陆页主 CTA 永远是「开始游戏」4 个字；明日方舟是「进入作战」。术语永远放在二级界面、且第一次出现时配一句话解释。

**建议**：
- 主 CTA 改成「开始游戏」或「继续旅途」（如果有存档）
- 「调律抽取」改名「档案抽取」或加图标 + 首次点击弹出一句解释："调律：从残响档案池中抽取角色资料与场景碎片"
- 第一次进入任何含术语的界面时，在界面顶部加一个**可关闭的术语小条**（不是 modal，不打断），如：「本页术语：调律 = 抽取档案的操作」

#### P0-2　状态栏信息密度过载

**位置**：`#status-bar`（行 843-855）

**现状**：5 个状态常驻显示，每个都有图标 + 标签 + 数值 + 进度条：
- 城邦稳定 / 世界失谐 / 粮药 / 音芯 / 奏者健康

在 480px 移动端容器里 5 等分 = 每个约 96px 宽，要塞下"城邦稳定 75"四个汉字 + ◇ 图标 + 进度条，必然挤成一团。`--font-size-13: 13px` 的字号在 96px 宽里换行都困难。

新玩家第一眼看不出哪个重要、哪个紧急。**5 个状态平等显示 = 等于没有重点**。

**大厂对照**：
- 明日方舟顶部 HUD：理智（关键资源）+ 当前关卡名，2 个元素
- 原神顶部：树脂 + 原石 + 缠结之缘，3 个，且都是图标+数字，无标签
- FGO：AP + 圣杯，2 个

**建议重构**：

```
桌面端（≥900px）：
┌─────────────────────────────────────────────────────────┐
│  ◆ 城邦稳定 75  ▓▓▓▓▓░   │  ⚠ 失谐 38  ▓▓░░░░  │  ⋯  │
└─────────────────────────────────────────────────────────┘
   ↑ 关键状态常驻显示          ↑ 危险状态突出         ↑ 展开按钮

移动端（<900px）：
┌──────────────────────────┐
│  ◆ 稳定 75  │  ⚠ 38  │ ⋯ │
└──────────────────────────┘
   只显示数值 + 危险高亮      点 ⋯ 展开 粮药/音芯/健康
```

- **关键状态常驻**：城邦稳定、世界失谐（这俩直接决定结局，必须可见）
- **次要状态折叠**：粮药、音芯、奏者健康 → 折叠到「⋯」展开面板
- **危险态视觉强化**：失谐 ≥ 70 时整个状态栏底色泛红脉动，不是只在数值旁标红
- **数值字号**：常驻数值至少 18px，标签可缩到 11px

#### P0-3　移动端字号过小

**位置**：`:root` 字号变量 + 全局应用

**现状**：
```
--font-size-xs: 12px      ← 状态栏、quick-actions、team-stat-grid、entry-bottom-strip 都在用
--font-size-13: 13px      ← status-item 主体字号
--font-size-sm: 14px      ← 默认次级文字
```

在 480px 容器里 12px 中文，需要眯眼。状态栏里的"城邦稳定 75"标签是 13px，等于把可读性压到极限。

**大厂对照**：
- 原神移动端正文 16-17px，HUD 标签 13px 是绝对底线
- 明日方舟战斗 HUD 数值 18-22px
- FGO 角色名 16px，技能描述 14px

**建议**：
- 引入新的字号阶梯：
  ```
  --font-size-mobile-floor: 14px;   /* 移动端任何可见文字不得低于此值 */
  --font-size-mobile-body: 16px;
  --font-size-mobile-label: 13px;
  --font-size-desktop-body: 15px;
  --font-size-desktop-label: 12px;
  ```
- 用 `@media (max-width: 899px)` 在移动端把所有 xs/13 强制升到 14
- 状态栏数值字号 = clamp(16px, 4vw, 20px)

#### P0-4　茶歇区无专属样式 + 无加载/错误状态

**位置**：`#tea-break-area`（grep 发现此 ID 只在注释里出现，没有专属样式定义）

**现状**：茶歇（AI 对话）复用 `#dialogue-area` 的剧情对话样式，但剧情对话是**单向展示**，茶歇是**双向输入**。当前没有：
- 输入框样式
- 发送按钮样式
- **API 等待状态**（0.5-3 秒界面卡住，玩家以为坏了）
- **网络失败状态**（无重试入口）
- 对话历史滚动区样式

这是工具四（边界状态设计）的重点对象。

**建议**：

```
茶歇对话区结构（独立于 #dialogue-area）：
┌──────────────────────────────────────────┐
│  ← 返回            槐序 · 共鸣 12         │  ← 顶栏：返回 + 当前对话对象 + 关系值
├──────────────────────────────────────────┤
│                                          │
│  [槐序] 今天的风有点冷。                  │  ← 对话历史，可滚动
│                                          │
│  [我]   ……                              │
│                                          │
│  [槐序] 你看起来很累。                    │
│                                          │
│         ✦ 槐序正在思考…                  │  ← 加载态：乐谱展开动画
│           （0.5-3 秒）                    │
│                                          │
├──────────────────────────────────────────┤
│  [输入框_________________________] [发送]│  ← 输入区，固定底部
│  ⚠ 网络异常 · 重试                       │  ← 错误态：内联在输入区上方
└──────────────────────────────────────────┘
```

加载态文案（延续白金歌剧美学）：
- "槐序正在思考…"（带名字，比通用转圈有人情味）
- "乐谱正在展开…"（首次连接 API 时）
- "回响正在汇聚…"（重试时）

错误态文案：
- "信号失谐，重试一次？"（按钮内联，不是 modal）
- 连续失败 3 次后："信号持续失谐，已切换至本地台词。"（自动降级，不卡玩家）

### 🟠 P1 级（明显影响体验，建议本轮修）

#### P1-1　CSS 三层覆盖 + 87 变量 + 60 透明色 token 的维护地狱

**位置**：`style.css` 整体

**现状**：
- 第 1 层：传统样式（行 300+）
- 第 2 层：VN 布局覆盖（行 2445+）
- 第 3 层：Final Cleanup 用 `!important` 强制覆盖（行 2724+）
- 第 4 层：Team Dossier Override（行 4051+，替代了行 320-489 的传统 team-select）
- 第 5 层：VFX Engine Styles 副本（行 3792+，由 `update_style.js` 自动合并）
- 87 个 CSS 变量 + 约 60 个自动生成的 `--tone-196-154-69-004` 透明色 token
- 文件内大量中文注释乱码（"鍏ㄥ眬褰㈠姝"= GBK→UTF8 转换失败疤痕）

**这不是直接的 UX 问题，但会拖慢所有 UX 改进的实施速度，是"间接 UX 债"**。每次想改一个按钮颜色，要查 3-4 个覆盖层，最后还得用 `!important` 打覆盖战。

**建议**：
- 长期目标：分层重构成单一权威样式 + 主题变量层
- 短期止血：
  1. 删除"被覆盖层完全替代"的传统样式段（如行 320-489 的传统 team-select 已经被行 4051+ 替代）
  2. 把 `--tone-196-154-69-004` 这种自动 token 改成 `color-mix(in srgb, var(--color-accent) 4%, transparent)`（已经在 Team Dossier 用了，是现代写法）
  3. 修复乱码注释（用 `chardet` 检测后批量转 UTF-8）
  4. 删除 `#opening-animation` 死代码（Final Cleanup 已经 `display: none !important`，但几十行动画样式还在维护）

#### P1-2　双套布局断点不连续

**位置**：`#game-container` + `@media (min-width: 900px)`

**现状**：
```css
#game-container {
  max-width: 480px;  /* 移动端 */
}

@media (min-width: 900px) {
  #game-container {
    width: min(1920px, calc(100vw - 32px)) !important;
    /* 强制 grid 布局 */
  }
}
```

**481px - 899px 中间没有任何过渡断点**。平板 / 折叠屏 / 中等屏幕（iPad 768px、Surface Duo 844px）会看到 480px 的移动端布局被拉伸到 800px，所有元素水平留白巨大、垂直挤压。

**建议**：
- 增加 768px 中间断点：
  ```css
  @media (min-width: 768px) and (max-width: 899px) {
    #game-container {
      max-width: 720px;
      /* 用单列但放大字号和卡片高度 */
    }
  }
  ```
- 或者把"480px 移动 + 1920px 桌面"改成"流式布局 + 桌面断点扩展"，避免硬切

#### P1-3　战斗日志 = 终端文本块

**现状**：单色 line-height: 1.75 的纯文本块，伤害数字、状态变化、行动结果都堆在一行行文本里。

**建议**：
- 短期：战斗日志改成"分段卡片"，每次行动一张小卡，含：行动者头像 + 行动名 + 代价 + 结果数值

#### P1-4　quick-actions 5 个按钮全文字 + 视觉密度低

**位置**：`#quick-actions`（行 861-905）

**现状**：5 个等宽文字按钮"队伍/茶歇/保存/读档/菜单"，min-height: 42px，font-size: 13px。

**问题**：
- 全文字，没有图标，视觉密度低，玩家扫一眼需要逐个读字
- "保存/读档"放一起，玩家容易误触
- "菜单"标了 `.danger` 类（红色边框），但"菜单"不是危险操作，这个标记很奇怪

**大厂对照**：
- 原神底部 tab：5 个图标 + 文字配合，常用功能居中
- 明日方舟底部：基建 / 作战 / 角色 / 任务 / 友情，图标为主，文字为辅

**建议**：
```
当前：[队伍] [茶歇] [保存] [读档] [菜单]

建议：[👥队伍] [☕茶歇] [⋯更多]   ← 常用 3 个居中
                            ↑
                     点击展开：保存/读档/设置/返回主菜单
```
- 常用功能（队伍、茶歇、更多）3 个常驻，配图标
- 保存/读档/设置折叠到"更多"
- 移除"菜单"按钮的 .danger 标记（除非它确实是"返回主菜单会丢未保存进度"的警告，那应该改名"返回主菜单"并保留红色）

#### P1-5　toast 位置在右上角 + 与状态栏冲突

**位置**：`#toast-area`（行 1255-1264）+ VFX 的 `#toast-area`（行 3799-3808，被覆盖到 top: 80px right: 32px）

**现状**：toast 显示在屏幕右上角。

**问题**：
- 移动端右手握持时拇指会挡住右上角
- 和顶部状态栏位置冲突（状态栏在 top: 0，toast 在 top: 80px 会重叠在状态栏下方）
- 关系值变化的 toast（VFX）和状态值变化的 toast（state-toast）共用同一个区域但样式不同，视觉不统一

**大厂对照**：
- 原神：toast 在屏幕中上方，避开 HUD
- 明日方舟：toast 在屏幕顶部中央，向下浮动后消失
- FGO：toast 在屏幕底部

**建议**：
- toast 统一到屏幕顶部中央偏下（top: 80px, left: 50%, transform: translateX(-50%)）
- 关系 toast 和状态 toast 用统一组件（同一样式系统，不同颜色边框区分类型）
- 移动端可考虑底部 toast（避开拇指区域）
